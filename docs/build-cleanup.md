# 빌드 정리 정책

## 확인된 대상과 실행 방법

Phaser 3 + Svelte 5/SvelteKit + Vite + adapter-static의 **웹 게임**이다. PC 브라우저와 모바일 브라우저를 CI에서 검사한다. 네이티브 PC/모바일/콘솔 패키징 설정은 없다. 로컬 Git 태그·CI·문서에서 실제 출시 여부를 확정할 수 없어 기존 `build/`는 출시/롤백 가능 자료로 보존했다.

빌드 도구는 Node.js 22 이상과 Python 3.9 이상, POSIX 파일 잠금(macOS/Linux/WSL)을 사용한다. Windows 네이티브 셸에서는 안전하지 않은 대체 잠금을 사용하지 않고 오류로 종료한다.

```bash
npm run build                        # 검증한 개발 패키지를 build 링크로 게시
npm run preview -- --host 127.0.0.1  # 기본 포트 4173, 정상 패키지에 읽기 잠금
npm run build:clean                  # 미사용 소유 작업 공간 회수 + 보관 정책 실행
npm run test:build-tools             # 작은 가상 패키지로 실패·중단·복구·보관 검증
npm run build -- --release v1.0.0    # 명시적 출시 보관본, 같은 이름 덮어쓰기 금지
```

`build/`는 `.build-artifacts/.../package`를 가리키는 상대 심볼릭 링크다. 호스팅에는 링크 자체가 아니라 **링크 대상의 내용**을 올린다. 이 도구는 외부 서비스에 배포하지 않는다. 별도 배포 파이프라인을 추가할 때도 검증한 불변 패키지를 업로드한 뒤 서비스의 버전 포인터를 교체해야 한다.

## 소유·종료·교체

- `.build-work/jobs/<작업 ID>/`에 약 1MiB 소스/설정 스냅샷, `.svelte-kit`, Vite 캐시, 패키지 후보와 OS 임시 파일을 생성한다. 큰 `static`과 설치 의존성은 읽기용 링크로 공유하며 복제하지 않는다. `.env*`는 작업 폴더 안에만 복사하고 종료 시 제거한다. 디렉토리는 사용자 전용 권한으로 생성한다.
- 프로젝트 전용 영구 `flock` 잠금으로 빌드·정리를 직렬화한다. 동시 작업은 기다리거나 파일을 삭제하지 않고 사용 중인 경로와 오류를 출력한다. 미리보기는 공유 잠금으로 현재 패키지를 고정하며, 실행 중에는 새 빌드/정리를 거절한다. `npm run dev`의 `.svelte-kit`/Vite 개발 캐시는 별도 경로라 빌드 청소와 충돌하지 않는다.
- 성공·실패 및 SIGINT(Ctrl-C), SIGTERM(CI 취소), SIGHUP 시 자식 작업 그룹을 종료하고 정리한다. 5초 안에 끝나지 않으면 해당 그룹만 강제 종료한다. 자식 Vite 프로세스도 잠금 FD를 상속하므로 감독 프로세스만 SIGKILL되어도 살아 있는 빌드의 파일을 지우지 않는다.
- 다음 실행은 운영체제 잠금과 기록된 작업 그룹의 생존 여부, 루트/종류/버전 소유 표식을 검사한다. 시간 경과만으로 활성 여부를 추정하지 않는다. 알 수 없는 표식·디렉토리·링크·마운트는 보존하고 경고한다. 표시된 문제를 조사하기 전 수동으로 잠금을 지우지 않는다. 전원 차단 중 표식 작성이 끝나지 않은 미확인 디렉토리는 자동 채택하지 않는다.
- adapter-static은 작업 공간 안에만 쓴다. HTML, 서비스 워커, 앱 매니페스트, 버전, JS와 원본 정적 에셋 해시를 검증한 후 패키지를 이동한다. 최신 포인터는 같은 파일시스템에서 원자적으로 교체한다. 실패한 빌드는 기존 포인터를 변경하지 않는다.
- 기존 디렉토리 `build/`의 최초 전환은 복제 없이 `preserved/<ID>/package`로 이동하며 SHA-256 목록과 복구 저널을 남긴다. 최초 이동과 링크 설치 사이에는 짧은 공백이 있을 수 있다. 그 구간의 중단은 다음 실행에서 보존본 링크로 복구한다. 이후 정상 포인터 교체는 단일 rename이다.

## 보관 범위

| 종류 | 위치 | 정책 |
| --- | --- | --- |
| 임시 소스 사본·캐시·컴파일 중간 파일 | `.build-work/jobs` | 작업 종료 시 제거, 비정상 종료 후 안전 회수 |
| 개발 성공 패키지 | `.build-artifacts/dev` | 최신 **2회**; 현재 포인터는 항상 보존 |
| 원문 빌드 로그 | `.build-artifacts/logs` | 최신 **10회**, 각각 마지막 **1MiB**; 내용은 요약하지 않으며 앞부분이 잘릴 수 있음 |
| 명시적 출시 보관본 | `.build-artifacts/releases` | 이름별 불변, 자동 만료/개수 제한 없음 |
| 기존 배포/롤백 가능 자료 | `.build-artifacts/preserved` | 자동 삭제 없음; 필요성 확인 후 별도 결정 |
| 크래시 분석용 소스 맵 | `.build-artifacts/symbols` | 임시 공간의 `.map`도 보수적으로 보존, 자동 삭제 없음; 현재 출시 설정은 맵을 생성하지 않음 |
| 기존 검증 자료 | `coverage`, `test-results`, `playwright-report`, `docs` | 이번 청소에서 보존. 도구의 기존 고정 출력 경로는 유지 |
| CI 빌드 로그·브라우저 보고서 | GitHub Actions artifact | 14일. 빌드 로그는 위의 1MiB 제한 적용; HTML/이미지/trace는 원문 로그가 아니므로 훼손하지 않음 |
| 공유 의존성·개발 캐시 | `node_modules`, 사용자 npm/브라우저 캐시 | 빌드마다 삭제하지 않음. 개발 캐시는 Vite가 동일 위치에 관리. 별도 용량/TTL 정책은 이번에 도입하지 않음 |

정리 중 오류는 `WARNING`과 남은 절대 경로로 출력하며 CLI는 실패 상태를 반환한다. 정리 실패가 정상 패키지를 무효화하지는 않는다. 심볼 보존에 실패하면 해당 작업 공간을 남긴다. 출시/심볼의 장기 보관은 개발 폴더 정책과 분리하며 실제 출시 시 외부 백업·패치 기준·소스 커밋·서명 자료 정책도 함께 확정한다.

CI의 두 작업 모두 실제 `npm run build` 경로와 `always()` 정리를 사용한다. 브라우저 작업도 Playwright의 기존 `webServer` 명령을 통해 같은 빌드를 호출한다. 러너 자체 강제 소실로 마지막 단계가 실행되지 않으면 다음 실행의 회수 또는 호스팅 러너의 작업 공간 폐기가 적용된다. 공유 npm 캐시는 유지한다.

## 예외와 변경 규칙

디버그 사본이 필요하면 `docs/build-debug-holds.md`에 **목적·담당자·위치·삭제 시점**을 먼저 적고, 관리되는 `jobs/dev/logs` 밖의 명시적인 보존 위치를 사용한다. 키/인증 정보가 포함되는 작업 공간 전체 복사는 피한다. 현재 디버그 보존 예외는 없다. 새 빌드/패키징 도구도 이 수명주기와 테스트를 확장해야 하며 날짜별 수동 복제나 넓은 `rm -rf`로 우회하지 않는다.

조사·실측·보존 해시: [disk-audit/report.md](disk-audit/report.md).
